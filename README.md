# iM뱅크 법인 고객 0값 패널티 스코어링

iM뱅크 2025 교육용 데이터(기준년월별 법인 고객 데이터)로 법인 고객의 예금·투자·대출 잔액, 계좌 수, 거래 건수와 금액을 0~100 점수 하나로 요약하는 팀 프로젝트입니다.

점수 계산의 특징은 두 가지입니다.

- **0값 패널티**: 스코어를 매기는 집단에서 0인 비율이 높은 피처일수록 그 피처 값이 점수를 덜 올리게 합니다.
- **업종별 계산과 외부 베타**: 업종마다 따로 스케일링·가중치를 적용하고, 기준년월·업종별 외부 베타(업종별 월별 신용공여 추이 자료)를 곱합니다.

## 점수 계산 방식

```
S = clip( β · rescale_0_100( Σ ω_i·α̂_i − λ · Σ ρ_i·α̂_i ), 0, 100 )
```

| 기호 | 뜻 |
| --- | --- |
| α̂_i | 피처 i를 최솟값·최댓값으로 [0, 1]에 옮긴 값 |
| ω_i | 피처 가중치(절댓값 합이 1이 되도록 정규화) |
| ρ_i | 스코어를 매기는 집단에서 피처 i가 0인 비율 |
| λ | 0값 패널티 강도 |
| β | 점수 보정 계수 |

피처 i의 실제 계수는 ω_i − λ·ρ_i가 되므로 0이 많은 피처의 영향이 줄어듭니다. 구현은 [`imbank_score/scoring.py`](imbank_score/scoring.py), 파라미터 값은 [`imbank_score/params.py`](imbank_score/params.py)에 있습니다.

두 가지 모델이 있습니다.

| | 업종별 모델 `score_industry.py` | 공통 모델 `score_common.py` |
| --- | --- | --- |
| 대상 업종 | 10개 업종: 교육 서비스업 / 농업, 임업 및 어업 / 수도, 하수 및 폐기물 처리, 원료 재생업 / 전기, 가스, 증기 및 공기조절 공급업 / 전문, 과학 및 기술 서비스업 / 정보통신업 / 도매 및 소매업 / 부동산업 / 사업시설 관리, 사업 지원 및 임대 서비스업 / 건설업. 그 밖의 업종은 점수가 비어 있음 | 전 업종 |
| 계산 단위 | 업종마다 따로 스케일링하고 ρ를 구함 | 전체 데이터 한 번 |
| 피처 | 법인_고객등급, 전담고객여부, 예금잔액, 투자잔액, 여신대출잔액, 예금비중, 대출비중, 여신_신용카드_좌수, 거래건수, 거래금액 (10개) | 법인_고객등급, 예금잔액, 투자잔액, 여신대출잔액, 대출비중, 신용카드사용금액, 거래금액 (7개) |
| ω, λ | 업종마다 다름 (λ 0.45~0.75) | 공통 (λ 0.6574) |
| β | 행마다 그 기준년월·업종의 베타. 2022년 1~3월은 2022년 4월 값, 베타가 없는 행은 1 | 0.99 (업종 베타 전체 평균) |
| 점수 범위 | 0~100 | 0~100 점수에 10을 더한 10~110 (업종별 모델과 점수 수준을 맞추기 위함) |
| 출력 | `outputs/score_beta.csv` (`--no-beta`면 `outputs/score_nobeta.csv`) | `outputs/score_all.csv` |

전처리([`imbank_score/preprocess.py`](imbank_score/preprocess.py))는 거래금액 범위를 빼면 두 모델이 같습니다.

- `1개초과3개이하` 같은 구간형 좌수·건수는 구간 중앙값(.5는 올림), `10개초과`는 10+5, `0개`·`1건`은 그 숫자로 바꿉니다.
- 예금잔액·투자잔액·여신대출잔액은 원본 CSV의 8~10번째, 11~13번째, 15~16번째 열을 합한 값입니다.
- 거래건수는 온라인(인터넷·스마트·폰뱅킹, 자동이체)과 오프라인(창구, ATM) 거래건수의 합입니다.
- 거래금액은 업종별 모델에서 `신용카드사용금액`~`요구불출금금액` 열의 합, 공통 모델에서는 신용카드사용금액을 따로 피처로 쓰므로 `창구거래금액`~`요구불출금금액` 열의 합입니다.
- 법인_고객등급은 일반·우수·최우수를 1·2·3으로, 전담고객여부는 Y·N을 1·0으로 바꿉니다.

## 실행 방법

Python 3.10 이상이 필요합니다. 테스트는 Python 3.11에서 pandas 2.3.3과 3.1.1로 확인했습니다.

```bash
pip install -r requirements.txt
```

### 데이터 준비

교육용 데이터와 베타 자료는 저장소에 포함하지 않습니다. `data/` 폴더를 만들고 다음 파일을 둡니다(모두 cp949 인코딩).

| 파일 | 쓰는 곳 | 형식 |
| --- | --- | --- |
| `data/(아이엠뱅크) 2025 교육용 데이터.csv` | 두 스크립트, 노트북 | 교육용 데이터 원본 |
| `data/Beta_Industry.csv` | `score_industry.py` | `기준년월` 열(`2022-04`, `202204` 등) + 업종명 열마다 베타 |
| `data/Beta_Industry_final.csv` | 노트북 | `월` 열(`YYYYMM`) + 업종명 열마다 베타 |

### 점수 계산

```bash
python score_industry.py               # 업종별 모델 -> outputs/score_beta.csv
python score_industry.py --no-beta     # 베타 없이 -> outputs/score_nobeta.csv
python score_common.py                 # 공통 모델 -> outputs/score_all.csv
```

다른 위치의 파일은 `--data`, `--beta`, `--output`으로 지정합니다. 출력 CSV는 `score` 열 하나이고 행 순서는 입력 데이터와 같습니다. 실행하면 베타 매칭 실패율(업종별 모델), 업종별 처리 건수, 점수 요약 통계를 출력합니다.

### 노트북

[`notebooks/외부데이터베타포함모델링.ipynb`](notebooks/외부데이터베타포함모델링.ipynb)는 10개 업종 각각의 월별 평균 점수 추이를 그립니다. Jupyter에서 `notebooks/` 폴더를 작업 폴더로 열면 `../data/`의 파일을 읽습니다.

## 결과

이 저장소에 남아 있는 결과는 노트북에 저장된 업종별 그래프 10장(2022년 1월~2024년 12월 월별 평균 점수)입니다. 그래프에서 읽은 근사값으로, 업종 평균 점수는 약 35~55 사이이고 업종마다 월별 변동 폭은 3점 안팎입니다. 이 월별 변화는 베타 변화만 반영합니다(아래 한계 참고).

실제 데이터로 계산한 점수 CSV는 저장소에 없습니다.

## 한계

- 데이터와 베타 자료가 저장소에 없어 저장소만으로 결과를 재현할 수 없습니다. 테스트는 합성 데이터로 계산 로직만 확인합니다. 베타 CSV를 만드는 코드도 저장소에 없습니다.
- 가중치·λ는 값만 있고 이를 정한 코드나 근거 자료는 저장소에 없습니다. 점수를 연체·신용등급 같은 외부 기준과 비교한 검증도 없습니다.
- 잔액 피처는 열 이름이 아니라 열 위치로 합산하므로 열 순서가 다른 자료에는 그대로 쓸 수 없습니다.
- 노트북은 각 달의 점수를 그 업종의 전체 기간 데이터에 그 달의 베타를 곱해 계산합니다. 그래서 월별 추이는 고객 데이터의 월별 변화가 아니라 베타 변화만 보여 줍니다.
- 노트북의 건설업 λ는 0.65로 `score_industry.py`의 0.6과 다릅니다.
- 공통 모델 점수(10~110)와 업종별 모델 점수(0~100)는 범위가 다릅니다.
- 노트북 그래프의 한글 폰트는 Windows의 맑은 고딕(`Malgun Gothic`)으로 지정돼 있습니다.

## 개발

```bash
pip install -r requirements-dev.txt
python -m pytest             # 합성 데이터 테스트
ruff check .                 # 설정은 pyproject.toml
```

- 잔액은 열 위치로 합산하므로 테스트용 합성 데이터([`tests/synthetic.py`](tests/synthetic.py))도 잔액 열을 그 위치에 둡니다. 입력 자료의 열 순서가 바뀌면 `preprocess.py`의 `*_POSITIONS` 상수와 합성 데이터를 함께 고칩니다.
- 업종별 모델의 피처 순서는 합산 순서를 정하므로 `params.py`의 `INDUSTRY_FEATURES` 순서를 바꾸면 점수가 소수점 아래에서 달라질 수 있습니다.
- 노트북의 업종별 셀은 따로 실행되도록 같은 함수를 셀마다 다시 정의하므로 ruff의 F811(재정의) 경고를 노트북에서만 끕니다.
